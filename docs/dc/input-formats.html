Input Formats and Batch Rules

Keyword grid

Each executable row needs a Search term. Symbol name is user-facing metadata and may be automatically identified; Gene locus appears only for search types that support it. Empty rows are ignored. The main grid removes control whitespace from ordinary fields, and ~ is an explicit blank placeholder in legacy/batch label flows.

BLAST input forms

  • Raw nucleotide or amino-acid sequence.
  • One or more FASTA records.
  • A supported Phytozome report URL or lemna JBrowse URL.
  • Rows transferred from Keyword Search.
  • A local file selected with Open..., or supported legacy load "file.txt" input.

For multiple queries, use one query per line unless supplying multi-line FASTA records. If labels are pasted as a parallel batch, provide one for every item or omit all of them; use ~ for an intentionally blank label. Generated FASTA headers contain no whitespace, but imported external headers may contain spaces.

Choosing a program does not biologically repair an incompatible query. Preserve the original source URL and identifiers when reproducibility matters.

Label names and aliases

label_name is the selected short name; labelname_type records how it was obtained; phgo_alias is a ranked alias list from the local Symbol Name database. Raw provider aliases, symbols, and synonyms remain source evidence. A manually entered or explicitly selected label is authoritative and is not silently replaced later.

Before submitting a batch

  1. Remove accidental blank records.
  2. Ensure FASTA records begin with > and sequence lines belong to the correct header.
  3. Use one supported URL per item.
  4. Ensure label count matches item count.
  5. Check molecule type against BLAST program.
